# Реестр шифров и сборок клиента

`config/cipher-profiles.json` сохраняет известные алгоритмы и профили отдельно от состояния текущего соединения. Запись профиля привязана к полному SHA-256 `Engine.dll`. Совпадение адреса сервера, порта или имени EXE для выбора профиля недостаточно.

В реестре зарегистрированы реализации `asterios`, `l2xor16`, `l2xor16-u64` и `plain`. Для Asterios добавлен проверенный профиль `config/monitor-profile.json` и ссылки на сохранённые подтверждения. Вариант `l2xor16-u64` увеличивает последние восемь байтов ключа как uint64LE на длину тела. Наличие реализации само по себе не означает поддержку других сборок. Новая сборка получает отдельную запись после анализа и проверки.

`src/check_classic_cipher_offline.py` проверяет вариант XOR16/64 по сохранённым исходным байтам x86-функции в Unicorn: 411 синтетических случаев, включая переносы uint32/uint64 и длины 1..32766, и 229 записей сохранённого соединения в обе стороны. Отчёт — `reports/new-client-decryption/native-xor-check.json`. Два внешних вызова CRT `memcpy_s` заменены явно указанным в отчёте копированием ровно восьми байтов; проверяется только преобразование тела, без запуска сетевой цепочки.

Статусы профиля: `candidate` — сохранён для дальнейшей проверки; `verified` — проверен, со ссылками на подтверждения; `rejected` — сохранён, но не используется автоматически. Автоматический поиск возвращает только точное совпадение SHA-256 со статусом `verified`. Проверка расшифровки не подтверждает дополнительные функции отправки пакетов.

## Чтение во время работы

```python
from l2_monitor.cipher_profiles import CipherProfiles

registry = CipherProfiles()
entry = registry.find(engine_sha256)          # отдельная копия записи либо None
profile = registry.load_profile(engine_sha256)  # проверяет SHA внутри JSON
status = registry.find(engine_sha256, verified_only=False)
```

`CipherProfiles` читает снимок реестра и не записывает файлы. Неизвестный SHA не подменяется ближайшей сборкой. Пути профилей и подтверждений относительны корню проекта; абсолютные пути и выход через `..` запрещены.

## Сохранение операторским сборщиком

```python
from l2_monitor.cipher_profiles import register_profile

register_profile({
    'id': 'new-client-build',
    'engine_sha256': engine_sha256,
    'algorithm': 'l2xor16',
    'profile': 'config/profiles/new-client.json',
    'evidence': ['reports/new-client/validation.json'],
    'validation': 'candidate',
})
```

Сборщик сначала сохраняет профиль и подтверждения, затем явно вызывает `register_profile`. Функция проверяет форму записи и поддерживаемый алгоритм, обновляет запись с тем же SHA либо добавляет новую, сохраняет остальные записи и атомарно заменяет JSON через временный файл в той же папке. Повреждённый исходный реестр не заменяется пустым. Одновременные операторские записи следует выполнять последовательно; атомарная замена защищает читателей от частичного файла.

Сессионные ключи, текущие счётчики, IV и словарь компрессии в реестр не записываются. Они принадлежат конкретному соединению и при повторном подключении получаются заново. Неизвестные поля записи отклоняются.
