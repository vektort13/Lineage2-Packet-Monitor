2026-11-21. Оба направления исходного PCAP расшифрованы: 1879 серверных и 125 клиентских прикладных пакетов. Начальные открытые ProtocolVersion и VersionCheck остаются в исходном PCAP. Это результат для данной записи и исследованной сборки, а не универсальный декодер всех версий Lineage 2.

Все 10 UserInfo содержат X501 и тот же мировой object ID `270128929`, что CharacterSelected. В записи есть 9 клиентских запросов движения и 17 серверных сообщений движения этого объекта. ## Полное направление server→client

Реализация [asterios_game_cipher.py](../src/asterios_game_cipher.py) восстановлена по фактической x86-функции клиента `0x053867ac`. Её результат и состояние ключа после каждого из 1235 сообщений совпали с изолированным выполнением оригинальных инструкций в Unicorn. Оригинальные страницы получены обычным ReadProcessMemory и сохранены с SHA-256; инструкции клиента не менялись. Чтение процесса требовалось для получения страниц кода, но не требуется готовому декодеру.

У Asterios есть несколько режимов, выбираемых по длине тела и номеру сообщения. Малые сообщения используют вращение участка ключа и меняют его байты; отдельные сообщения передаются открыто; другие используют running XOR. Поэтому один стандартный XOR не мог обработать весь обмен. Начальный счётчик 0 подтверждён согласованностью всего захвата и совпадением с оригинальным кодом.

Байт `0x8d` после преобразования действительно направляется обработчиком `0x053874d4` в распаковку. Все 127 таких блоков успешно обработаны одним продолжающимся raw DEFLATE-контекстом. Внутренние полные длины u16 LE согласованы на всей записи; дырок TCP и конфликтующих перекрытий нет. Остальные тела восстановлены как обычные пакеты с внешним заголовком длины. Это проверка расшифровки и границ всех сообщений, а не полная расшифровка смысла каждого поля.

Найдены CharacterSelectionInfo с X501, CharacterSelected с X501, MoveToLocation, UserInfo и DeleteObject. Названия остальных opcode остаются сопоставлениями со справочником NetPro.

Повторение из папки проекта, без обращения к процессу игры:

```powershell
python src/decode_prime_server.py reports/network-20261121-134122/prime-relogin.pcapng --output-dir reports/decryption-20261121/offline-prime --native-reference reports/decryption-20261121/emulation-server-sequence.json
```

Результаты: полные байты (`reports/decryption-20261121/offline-prime/server-packets.bin`), индекс и контрольные суммы (`reports/decryption-20261121/offline-prime/server-packets.json`), сравнение с оригинальным x86 (`reports/decryption-20261121/native-python-equivalence.json`). SHA-256 результата: `f014bd278bfd2618e6061de1505d2eabd6c89e4170ebd9ebf6c64cb032bf0fbe`.

## Проверенный пакет

Исходная запись: `reports/network-20261121-134122/prime-relogin.pcapng`, SHA-256 `8c9a3c7fde74067f4c9d638b3603ebdcad568148d3ac10e53b90f9ceffc80582`. Второе внешнее серверное сообщение находится в TCP-кадре 8 и имеет длину 151 байт.

Последовательность обработки: сборка TCP по sequence numbers → внешняя полная длина u16 LE → running XOR тела с начальным 16-байтовым материалом из позиций 4–19 первого сообщения сервера → пропуск первого полученного байта 0x8d → raw DEFLATE (`wbits=-15`) → внутренний пакет с полной длиной u16 LE.

| Проверка | Результат |
|---|---|
| Распаковано | 408 байт |
| Внутренняя объявленная длина | 408 байт |
| Opcode | 0x09 |
| Название по NetPro | CharacterSelectionInfo |
| Число персонажей | 1 |
| Максимум персонажей в начальных полях | 7 |
| Имя X501 в UTF-16LE с терминатором | Смещение 17 внутри внутреннего пакета |
| Непотреблённый или лишний сжатый хвост | 0 байт |

Полученный блок заканчивается границей сброса сжатия; `inflate.eof == false` не означает, что пакет обрезан. Внутренняя длина полностью согласована. Назначение оболочки 0x8d впоследствии подтверждено обработчиком и всей записью, как описано выше.

Отчёт: first-server-decoded.json (`reports/decryption-20261121/first-server-decoded.json`). Полные расшифрованные байты: first-server-packet.bin (`reports/decryption-20261121/first-server-packet.bin`). Двоичный пакет содержит данные тестовой учётной записи и остаётся в локальной игнорируемой папке reports.

## Полное направление client→server

В C2S отдельно преобразуется заголовок длины; состояние длины развивается по служебному последнему байту тела, opcode и длине. Для первого сообщения низкие 16 бит состояния `0xa8fc` восстановлены из его размера 64. Эта гипотеза затем проверена всеми последующими границами: полностью разобраны 2902 байта после ProtocolVersion, получены 125 сообщений без хвоста. Границы TCP-порций для такого вывода не использовались как готовые границы всех сообщений.

Исходящий счётчик `0x053b5248` независим от серверного `0x053b5244` и начинается с 0 в исследованном соединении. Оригинальная функция `0x0538660c` реализует преобразование тела. Для 122 сообщений перед XOR обнаружен разворот порядка байтов, для 3 использован прямой XOR. Один служебный байт оболочки удалён из каждого восстановленного прикладного пакета. Получено 2777 байт; SHA-256 `ea10861f872571e0e2b63196a12cb67bebb655ef139d377c705fbf190ba1bb7c`.

Декодер получает маску посредством изолированного запуска исходной функции на нулевых данных, проверяет кандидата обратным шифрованием исходной функцией и принимает только точное совпадение с перехваченным шифротекстом. Состояние ключа для следующего сообщения берётся из этого проверенного прямого шифрования. Так проверены тела всех 125 сообщений. Штатная отправка сетевых пакетов не вызывается; инструменты исполняют только сохранённые инструкции внутри Unicorn.

Результаты: полные клиентские пакеты (`reports/decryption-20261121/offline-prime/client-packets.bin`), индекс, происхождение страниц и проверки шифротекста (`reports/decryption-20261121/offline-prime/client-packets.json`). Повторный запуск без live-pid дал идентичные 2777 байт. Клиентская реализация пока использует сохранённые страницы кода и локально установленный Unicorn 2.1.4; серверная реализована на чистом Python. Описание каждого поля всех opcode не входит в подтверждённый результат.

Наблюдения обычными Windows API выполнялись только на чтение, без записи в процесс, отладчика или перехватчиков. Изначальный поиск ключа был ограничен адресами ниже 2 GiB; позднее действующий CClientSocket найден по указателю UNetworkHandler в доступной области выше 2 GiB. Предыдущий отрицательный поиск не показывал отсутствие или сокрытие ключа. REA Rizin недоступен на текущем PATH; дизассемблерные наблюдения Capstone и изолированная эмуляция не обозначаются как REA Evidence.

Проверенная штатная кнопка записи сохранила AVI, а не сетевые события. Эта запись остановлена. После уточнения пользователя окно игры больше не используется для исследования; анализ продолжается на локальных артефактах и PCAP.
