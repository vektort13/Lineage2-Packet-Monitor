# План первого работающего прототипа

Это план следующих этапов, а не описание уже реализованных функций.

1. Зафиксировать JSONL-формат событий и правила проверки. Обязательные поля: `schema_version`, `run_id`, `source`, `session_id`, `seq`, `ts_utc`, `event`, `observer_id`, `object_id`. Ключ состояния: run + сессия наблюдателя + наблюдатель + объект. Не смешивать повторные подключения и повторно используемые Object ID.
2. Разделить независимые факты: ожидаемая видимость сервера, KnownList, отправка события клиенту, наблюдение на клиенте. Отправка не означает получения или отрисовки. Отсутствующее наблюдение обозначать `unknown`, не `false`.
3. Для наблюдений добавить `visible`, `targetable`, `interaction_result`, `observation_method`; для состояния — координаты, регион и причину перехода. Время хранить в UTC, последовательность — отдельно для каждого источника. Предусмотреть погрешность часов и окно стабилизации; не выводить причинность только из отметок времени.
4. Реализовать загрузку/валидацию JSONL, восстановление состояния и сопоставление направленных пар A→B и B→A. Синтетические данные могут задавать стабильные идентификаторы и согласованные часы.
5. Подготовить сценарии: штатное появление/исчезновение, одностороннее расхождение, взаимное расхождение, неполные наблюдения, события с одинаковым временем, повторный вход и повторное использование Object ID.
6. Создать вывод JSON/CSV/Markdown с исходными номерами строк, временными интервалами, значениями каждого слоя и явными неизвестными. Детектор сообщает наблюдаемое расхождение, но не присваивает гипотезе статус доказанной причины.
7. Добавить `unittest` для корректного обнаружения расхождений, отсутствия ложных срабатываний при штатном переходе и неполных данных, обработки испорченной строки, отдельных сессий и временного окна.
8. Затем добавить адаптер конкретного серверного журнала. Не считать произвольный текстовый лог готовым источником KnownList: при отсутствии событий сначала потребуется инструментировать собственный сервер.

Критерий готовности: одна CLI-команда читает синтетический JSONL, выдаёт воспроизводимый отчёт, обнаруживает заданные направленные расхождения и не выдаёт неизвестные наблюдения за невидимость. Команда и ожидаемые результаты будут записаны в README после реализации.
