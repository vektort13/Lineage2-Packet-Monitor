# Локальный монитор пакетов

Запуск: `Start Monitor.cmd` или `python src/monitor.py --open` из папки проекта.
Интерфейс: http://127.0.0.1:8765. Документация API: http://127.0.0.1:8765/api/docs.

Монитор находит игровой процесс и его TCP-соединение, выбирает физический
интерфейс Npcap, собирает TCP-потоки и публикует проверенные расшифрованные
пакеты. Обычная задержка публикации — 4–6 секунд. Для сжатых блоков используется
реальный словарь DEFLATE работающего клиента; проверяются конечный словарь,
число распакованных байтов, ключи и счётчики. Клиентский шифротекст повторно
воспроизводится оригинальной функцией в Unicorn.

Профиль `config/monitor-profile.json` привязан к осмотренной сборке и раскладке
памяти Asterios. Проверяются хеш Engine.dll и участки кода. После обновления или
изменения расположения кода может потребоваться новый профиль. Возможность
читать этот клиент не означает поддержку любого другого сервера.

## Что доступно

- Цвет по смыслу сообщения: движение, появление, удаление, бой, обучение,
  предметы, обмен, выбрасывание, поднятие, диалог, состояние и ошибки.
- Галочки для нескольких категорий и конкретных типов `направление:opcode`.
  Пустой выбор скрывает все пакеты. Фильтры сохраняются в браузере.
- Поиск по именам, opcode и разобранным полям, включая Object ID.
- Поля выбранного пакета, HEX, SHA-256 и признак распаковки.
- Редактирование отдельной копии; HEX ↔ обратимый текст в UTF-8, UTF-16LE,
  Windows-1251 и Latin-1. `\xNN` обозначает отдельный байт; `\\` — обратную косую.
  Кнопка обновления u16 длины и сохранение JSON/BIN.
- Автовыбор проверяемого преобразования или ручной выбор Asterios, L2 XOR16,
  открытого тела. Неподходящий режим не публикует неподтверждённый результат.
- Предметы вокруг из полученных DropItem/SpawnItem, координаты, количество,
  расстояние XY при известной позиции, подтверждения GetItem/DeleteObject.
  Action по предмету отдельно обозначается как запрос. После пропуска интервала
  ранее видимые предметы получают состояние «Нужно обновление».
- Сохраняемый справочник Item ID и Skill ID/уровней. SQLite:
  `reports/monitor-library/catalog.sqlite`; JSON с примером пакета и CSV для
  сравнения серверов. Записи разделены по IP:порту и профилю; одинаковый ID
  на другом сервере автоматически не получает прежнее название.

В памяти остаются последние 10 000 пакетов, в браузере — 1200 строк. Захват
использует кольцо из двух файлов, журналы — три файла до 5 МБ каждый.
Справочник сохраняется отдельно и переживает перезапуск. Эксперименты с PCAP
не удаляются автоматически. Названия большинства предметов и умений ещё не
извлечены; для них показывается ID. Gold/Silver подписаны по проверенному
эксперименту на этом сервере.

## API

GET `/api/info` возвращает категории, режимы и токен для POST-заголовка
`X-Monitor-Token`. Сервер слушает только loopback и проверяет Host/Origin.

| Метод | Путь | Данные |
|---|---|---|
| GET | `/api/status` | Процесс, соединение, счётчики и результаты проверок |
| GET | `/api/processes`, `/api/interfaces` | Найденные процессы и интерфейсы |
| GET | `/api/packets?after=0&limit=250` | Пакеты без полного HEX, cursor/more |
| GET | `/api/packets/{id}` | Полная запись с raw_hex |
| GET | `/api/types`, `/api/items` | Типы пакетов и наблюдаемые предметы |
| GET | `/api/export` | Буфер пакетов в JSONL |
| GET | `/api/library` | Справочник: kind=item/skill, server, search |
| GET | `/api/library/export?format=json` | JSON с образцами; format=csv для таблицы |
| POST | `/api/start` | `{pid:null, interface:"auto", cipher:"auto"}` |
| POST | `/api/stop` | `{}` |
| GET / POST | `/api/ciphers`, `/api/cipher` | Список режимов / выбор `{cipher:"auto"}` |
| POST | `/api/convert` | mode, hex/text, encoding, update_length |
| POST | `/api/drafts` | hex, encoding, необязательный packet_id |
| GET | `/api/drafts/{id}[.bin]` | Копия JSON или BIN |
| POST | `/api/decrypt` | Офлайн-тело S→C: hex, cipher, key, counter |
| GET | `/api/sender` | Доступность отправки и причина ограничения |
| POST | `/api/send` | Повтор C→S с подтверждением новых исходящих байтов |
| GET | `/api/client-catalog` | kind=items/skills, search, offset, limit |
| GET / POST | `/api/packet-queue`, `/api/packet-queue/start` | Очередь / запуск repeats, interval_ms |
| POST | `/api/packet-queue/add`, `/pause`, `/stop`, `/clear` | Копии и управление выполнением |

Фильтры `/api/packets`: `categories=movement,inventory`,
`types=server:21,client:B0`, `direction=client`, `search=4356`.
Отсутствующий параметр означает все значения, пустой `categories=`/`types=` —
ни одного. `after` — последний cursor, limit 1–1000. `history_truncated`
показывает, что старые данные уже вышли из буфера.

## Проверка отправки

Прототип однократного вызова штатной функции отправки проверен на реальном
соединении. Исходный запрос `03 00 50` не появился на проводе. Клиент вместо
него отправил `Packet Fake Send Thrd [0x50] 21896 != 125724`.
Диагностический текст указывает на возможное несоответствие потоков, но
точный компонент и механизм пока не установлены. Возврат функции не является
доказательством отправки запроса. [Диагностика](fake-send-thread-diagnostic.md).

В том прототипе отправка была отключена (`runtime_enabled:false`), кнопка
оставалась неактивной. Текущая очередь подключена отдельно: проверенные
обработчики действий и общий путь c/cb в игровом UI-потоке с проверкой
фактических исходящих байтов. Живая проверка общего пути пока не завершена.
[Текущее состояние и проверки](client-catalog-and-queue.md).
Проверки защиты не менялись. В первоначальном опыте обучение и запрос уровня 9
в игру не отправлялись.
Прототип переходника выполнял код в процессе игры; он не был пассивным
наблюдением. [Подробности опытов](action-experiments.md).

## Проверки

`python -m unittest discover -s tests -v` — разбор TCP, шифры, словарь,
редактор, фильтры, предметы, справочник, схемы обучения и блокировка отправки.

`python src/check_monitor_browser.py` — отдельный headless Chrome с временным
профилем: таблица, цвета, редактор/BIN, сохранность исходника, UTF-16LE,
галочки категорий и типов, справочник. Результаты и снимки —
`reports/monitor-browser-test/`.
