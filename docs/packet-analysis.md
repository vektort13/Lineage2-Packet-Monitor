# Пассивная запись трафика X501 / Prime

Дата: 2026-11-21, Asia/Dubai. Захват выполнен. Затем расшифрованы оба направления этой записи: 1879 серверных и 125 клиентских прикладных пакетов. Ниже сохранены сведения о захвате и история первоначальных проб. [Итоговая проверка и воспроизведение](decryption-progress.md).

## Что наблюдалось

Процесс AsteriosGame, PID 65124, окно Asterios Prime, подключён к 146.59.110.40:2110. В игровом мире наблюдался X501. Первое соединение использовало локальный порт 28733; новое соединение — 26087.

Запись выполнена Npcap/Dumpcap 4.0.6 на Ethernet 3. Стек: Ethernet → PPPoE → PPP → IPv4 → TCP. Фильтр ограничивал запись выбранным адресом и портом, учитывая PPPoE. Игровые сообщения не изменялись и не воспроизводились.

| Запись | Сетевых кадров | Длительность | Начало соединения |
|---|---:|---:|---|
| prime-passive.pcapng | 322 | 44.901 с | SYN отсутствует |
| prime-relogin.pcapng | 1465 | 175.721 с | Есть SYN и SYN-ACK |

Оба процесса захвата завершились штатно. Dumpcap сообщил 0 отброшенных кадров на интерфейсе в обоих случаях. Это показатель захвата, а не измерение всех возможных сетевых потерь. Усечённых кадров не обнаружено.

Данные каждого направления собраны по TCP sequence numbers. В захваченных диапазонах не обнаружены дырки или конфликты перекрывающихся байтов. Граница TCP-сегмента не считалась границей игрового сообщения.

В первой записи server→client содержит 8020 байт полезной нагрузки, полностью разбираемых на 291 кандидат сообщения по двухбайтовой little-endian полной длине. Client→server содержит 491 байт; тот же формат с первого доступного байта не подошёл. В записи нового соединения server→client разобран на 1236 кандидатов сообщений. Согласованная длина ещё не устанавливает смысл сообщения или opcode.

## Начальный обмен

Первое сообщение нового клиентского соединения: длина 267, первый байт тела 0x0e, следующий 32-битный little-endian параметр — 448. Интерпретация параметра как заявленной клиентом версии протокола соответствует структуре ProtocolVersion в выбранной открытой реализации [3]. Соответствие конкретным хроникам Asterios этим не установлено.

Первое серверное сообщение: длина 34, первый байт тела 0x2e, следующий байт 1. Далее наблюдается блок, похожий на материал ключа. Это кандидат KeyPacket; точная раскладка полей Asterios не подтверждена.

Для server→client гипотеза о незашифрованной двухбайтовой полной длине последовательно покрыла весь доступный поток. Для client→server она разбирает начальное сообщение, но не объясняет последующие байты с выбранной позиции. Возможны иная обработка заголовков, дополнительное преобразование либо неподходящий формат разбора. Само различие не устанавливает механизм защиты.

## Первоначальные проверки расшифровки

Проверена одна конкретная гипотеза: 16 байт с позиций 4–19 первого серверного сообщения используются как исходный ключ, далее применяется running XOR из открытого Encryption.java [1], со счётчиком в байтах ключа 8–11 и отдельным состоянием направления. Обработано 1235 последующих server→client сообщений. Имя X501 в UTF-16LE в полученных кандидатах не найдено, согласованная семантика пакетов не подтверждена. Отсутствие имени само по себе не доказывает шифрование или неверность алгоритма.

**Первый результат:** после пропуска первого байта 0x8d и распаковки raw DEFLATE первый кандидат дал согласованный внутренний пакет длиной 408 байт: opcode 0x09, один персонаж, имя X501. Позднее по оригинальному коду восстановлены режимы преобразования и отдельные счётчики направлений; весь захват расшифрован и проверен. Ранние результаты стандартного XOR остались неподтверждёнными гипотезами и не используются как готовая расшифровка остальных сообщений.

В выбранном L2J Mobius ProtocolVersion вызывает enableCrypt, KeyPacket сериализует часть материала ключа, а Encryption содержит преобразование тела [1–4]. Код этой реализации — проверяемый образец, а не описание Asterios или оригинального сервера NCSoft.

## Артефакты и воспроизведение

Папка записи (`reports/network-20261121-134122`) содержит:

- prime-passive.pcapng и prime-relogin.pcapng — исходные записи.
- capture-manifest.json и relogin-manifest.json — фильтры и условия.
- summary.json и relogin-summary.json — структура потока и SHA-256 записей.
- reference-xor-probe.json — параметры и результат неподтверждённой гипотезы расшифровки; ключ в текстовый отчёт не перенесён.

Из папки проекта:

```powershell
python src/capture_summary.py reports/network-20261121-134122/prime-relogin.pcapng --output reports/network-20261121-134122/relogin-summary.json
python -m unittest discover -s tests -v
```

capture_summary.py читает существующий PCAPNG через локальный TShark, собирает TCP-диапазоны и проверяет гипотезу заголовка. Он не подключается к игре и не расшифровывает её. Все 5 тестов прошли: проверены фрагментация/объединение сообщений, перестановка/повтор сегментов, дырки, конфликтующие байты, переход sequence number через 2³² и неполные заголовки.

REA inspect_pcap_capture вернул capability_unavailable: его процесс не получил абсолютные пути TShark/Capinfos. Анализ выполнен напрямую установленными Wireshark CLI по абсолютным путям. Эти результаты не обозначаются как REA Evidence. Конфигурация MCP не изменялась.

Для исследования видимости следующий воспроизводимый шаг — собственный совместимый сервер с журналированием сообщений до шифрования и сопоставлением с PCAP. Для Asterios уже доступны пассивная временная шкала, направления и размеры; семантический разбор требует отдельно подтвердить фактическую схему протокола.
