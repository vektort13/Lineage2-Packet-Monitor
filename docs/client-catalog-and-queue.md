# База клиента и очередь

Из живого клиента 65124 извлечены все записи двух таблиц: 28 690 предметов
и 84 004 записи скиллов/бафов, соответствующие 12 852 уникальным ID скиллов.
Баффы хранятся в общей таблице скиллов. Их имена и описания доступны
в разделе «Скиллы и бафы», а имена активных бафов — в дополнительных опциях.
Количество записей относится к этой версии клиента, а не к содержимому сервера.

Вкладка «База клиента» содержит поиск по ID, названию и описанию скилла,
постраничный просмотр всей таблицы и экспорт полного JSON. Начальная база
включена в EXE; при подключении программа перечитывает её из клиента.
Инвентарь и меню скиллов используют эту базу независимо от наличия предмета
или скилла у персонажа. Уровни изученных скиллов по-прежнему берутся из
серверного SkillList. Название выбирается для точной пары ID/уровень.

Данные: `config/client-catalog.json`. Сводка извлечения:
`reports/buff-analysis/client-catalog-summary.json`.
Чтение только памяти: UI UIDATA_SKILL.GetName → helper fb84f350 →
fb819a70 → fb819110 → Engine 20424380. Корень таблиц Engine+8e7c48;
указатель TMap предметов +10a8, TMultiMap скиллов +1b580.
Узел 12 байт: следующий индекс, ID, указатель записи. Запись скилла:
FString названия +0, FString описания +0c, ID +18, уровень +1c.
Имя предмета: индекс FName +b4; Core массив FNameEntry и UTF-16 +12.
Профиль хранит проверяемые байты обработчиков. Границы таблиц, уровни,
ID и строки проверяются; не найденные имена не выдумываются.

Очередь ранее была только хранилищем копий с отключёнными кнопками.
`QueueRunner` добавляет выполнение снимка очереди, циклы, интервал,
паузу между вызовами, остановку и отмену при смене сессии/пропуске захвата.
Весь список проверяется до первой отправки. Неопределённый вызов не повторяется.
Результат считается отправленным только при совпадении клиентских байтов
с новым исходящим пакетом в проверенном захвате. Это подтверждает передачу
запроса, но не выполнение действия сервером.

Пакеты S→C используют другой протокол и серверу как C→S не отправляются.
Для 19, 23, 50, 73, 7C используются ранее проверенные оригинальные
обработчики. Другие C→S передаются штатному сериализатору в игровом UI-потоке:
формат c для одного opcode, cb для opcode и неизменённого бинарного хвоста.
Перед вызовом проверяются сохранённые SHA-256 кода, socket vtable и подключение.
Максимальный полный пакет — 32768 байт. Длина добавляется клиентом, затем
применяются его текущие таблицы opcode, шифрование и транспорт.

Проверка общего пути на собственном native mock подтверждает ABI и точные
байты. Живая проверка новой формы c/cb пока не выполнена: во время её
запуска игровой процесс уже был закрыт. `raw_replay_live_verified=false`
сохраняет это различие. Ранее проверенный способ b отправлял CMPF0 вместо
целевого запроса; его результат не выдаётся за подтверждение новой реализации.
Если клиент откажет в произвольном повторе, очередь завершится ошибкой
без автоматического повтора. Защиты клиента и проверки сервера не меняются.

Проверки: `tests/test_client_catalog.py`, `tests/test_queue_runner.py`,
встроенная проверка UI, собственный нативный mock процесса и ABI.

Финальная сборка: 137 unit-тестов и 171 проверка встроенного UI/ABI прошли.
`reports/final-client-catalog-test/self-test.json` — проверка готового EXE.
`reports/buff-analysis/frozen-catalog-queue-smoke.json` — запуск EXE,
контроль SHA-256 встроенной базы, API поиска/страниц, ручной интервал автохила
и отказ в отправке при остановленном захвате. Сеть в этой проверке не использовалась.
`reports/buff-analysis/queue-formatter-offline.json` — оригинальный сериализатор
в Unicorn: c и cb сохраняют байты в трёх проверенных примерах, включая D0.
Для большого буфера в сохранённых страницах не хватает страницы 2185e000;
эта ветка не считается проверенной. Профиль сохраняет отсутствие живого подтверждения.

## Завершение оффлайн

По поручению пользователя дальнейшая работа выполнена без запуска игры и
без ожидания игрового подключения. Более полная проверка закрыла ограничение
первоначального отчёта по большому буферу: недостающая страница содержит флаг
выбора оптимизированного CRT-копирования. В Unicorn задано и явно записано
состояние этого флага 0 — оригинальная скалярная ветка memcpy. Исполняемые
байты сериализатора и memcpy не заменялись. Это тестовая CPU-среда, а не
утверждение о состоянии памяти игрового процесса.

`python src/check_packet_replay_offline.py` проверяет 520 искусственных примеров
от одного до 32766 байт тела и все 125 ранее сохранённых клиентских пакетов.
Проверяются SHA-256 исходных записей, точное сохранение байтов, длина результата
и защитные области перед/после выходного буфера. Результат:
`reports/offline-finish/serializer.json`, все 645 примеров прошли.

`python src/check_queue_offline.py` запускает только собственный native mock,
выполняет 125 сохранённых пакетов в трёх циклах и строит тестовый захват
после независимой проверки полученных аргументов. 375 нативных вызовов
завершены с сохранением порядка; история ограничена 100 записями.
Результат: `reports/offline-finish/native-queue.json`. Этот захват моделируется
тестом и не является сетевым подтверждением сервера.

Отправитель и очередь теперь принадлежат Monitor и используются совместно
окном и API. Прямой API-вызов не может вклиниться в выполняющуюся или
приостановленную очередь. Фоновые действия приостанавливаются и при прямой
отправке. Остановка захвата отменяет оставшуюся очередь. Необычные структуры
клиентских пакетов направляются в общий путь вместо отказа частичного парсера.

Полнота базы проверена отдельно: 28690 уникальных ID предметов, 84004
уникальные пары ID/уровень и 12852 уникальных ID скиллов. В исходном клиенте
один предмет и 21 запись скилла не имеют имени; программа сохраняет это
содержимое. Отчёт: `reports/offline-finish/catalog.json`.

После этих изменений прошёл 141 unit-тест. Проверка готового EXE включает
нативную передачу максимального буфера, ручное использование предмета при
полном HP и проверку интерфейса без подключения к игре. Реальная обработка
запросов сервером остаётся вне оффлайн-проверок; игра для них не требуется.
