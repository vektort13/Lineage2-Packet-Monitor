# Newbie Buff, автохил и данные персонажа

## Подтверждённый обмен Newbie Guide

Во время ручного получения бафов записаны семь одинаковых C→S 23:
`09 00 23 30 00 31 00 00 00` — UTF-16 команда `01`.
Предшествующий S→C 19 содержит object ID NPC 268440888 и его меню
`Newbie Guide:` с `bypass -h 01` / `Give me some support magic.`.
S→C 48 подтверждает применение умений 4322–4327 и 5637 первого уровня
к персонажу X501. S→C 85 содержит u16 count и десятибайтные записи
`u32 skill_id, u16 level, i32 remaining_seconds`.

«Дополнительные опции» → Newbie Buff принимает количество и «Старт».
Перед серией штатный Action открывает нужного NPC в пределах 300 единиц;
свежее серверное меню должно совпасть. Затем оригинальный UIScript
RequestBypassToServer вызывается в игровом потоке N раз без пауз.
Это серия самостоятельных штатных запросов в TCP, а не склейка разных
команд в один прикладной пакет. Сырой отправитель пакетов не используется.

Учёт разделяет число вызовов, наблюдаемых C→S 23 и серверных наборов.
Набор требует семь разных S→C 48 от выбранного NPC именно собственному
персонажу и собственный S→C 85 с эффектами. Обновления 85 могут объединять
несколько наборов. Время показывается по серверу, без умножения на N.
Смена цели или другое меню отменяют отправку; отказ не повторяется автоматически.

`reports/buff-analysis/live-batch-10.json`: десять запросов за одну серию,
70 соответствующих применений, семь объединённых обновлений статусов.
Остаток эффектов — 3599–3600 секунд. `batch-engine-live.json` сохраняет
отдельную неуспешную проверку, где запросы наблюдались, но сервер не выдал
эффекты. Её результат не подменён успешным.

## Данные клиента

GetItemName, GetPlayerInfo, GetUserInfo и RequestUseItem найдены по UFunction
в работающем клиенте. Настоящие названия читаются из той же таблицы предметов
и FName, которую использует GetItemName. Из 44 строк текущего инвентаря
найдены Greater Healing Potion (1061) и Elixir of Life (No Grade, 8622).
Имена записаны в `reports/buff-analysis/inventory-names.json`.

Собственный actor определяется по штатной цепочке manager; его object ID
сопоставляется с записью персонажа. Проверены совпадение ID и поля UserInfo:
`nLevel` имеет смещение 0x34, `nCurHP` — 0x44, `nMaxHP` — 0x48.
Код заполнения UserInfo читает их из записи персонажа по смещениям
0x88, 0xB4 и 0xB0 соответственно; ник расположен по 0x1C.
Сохранены `user-info-properties.json` и профили соответствующих функций.
В игре прочитаны X501, уровень 21, HP 727/727 и изменение HP при уроне.

Модули UI, Engine и Core проверяются по коду с перемещениями абсолютных
адресов; процесс и соединение — по PID, времени создания и endpoint.
Чтения используют обычный доступ только для чтения. Имена кэшируются для
данного процесса, HP читается каждые полсекунды. Неопределённые данные
не используются для применения предмета.

## Автохил

Галочка изначально выключена. Пользователь выбирает хилку по названию,
порог 1–99% и интервал 1–3600 секунд; текущий начальный интервал — 11 секунд.
Падение строго ниже порога включает цикл до 100%. На 100%, при смерти,
остановке захвата, отсутствии выбранной хилки или неполном инвентаре
нового применения нет. На время других автоматических действий лечение
приостанавливается. После изменения интервала активный цикл сохраняется,
а следующая попытка отсчитывается от предыдущей.

Непосредственно перед UseItem штатная функция заново получает запись
персонажа в игровом потоке. При нуле или полном HP предмет не применяется.
Используется обычный обработчик клиента, результат виден в C→S 19,
серверных InventoryUpdate и MagicSkillUse. Параметры применения передаются
из актуального object ID выбранного стека, а не из ID шаблона.

`auto-heal-damage-live.json`: после урона отправлены шесть C→S 19
с интервалами примерно 1.05 секунды; сервер уменьшил 1061 с 33 до 32 и
применил умение 2032. Следующие попытки получили S→C 62 / 2303 с item ID
1061 и временем 9, 8, 7, 6, 5 секунд. После этой проверки добавлен ручной
интервал; по уточнению пользователя начальное значение изменено на 11 секунд.
`auto-heal-full-live.json` не проверил повторный цикл: HP за период
наблюдения не опустилось ниже порога, попыток было ноль; конечное HP 100%.

## Проверки

`test_buffs.py`, `test_auto_heal.py`, API и встроенная проверка EXE покрывают
количество серии, совпадение NPC и собственного персонажа, объединённые
статусы, отказ без ложного успеха, выбор хилки и её реальное имя, порог,
фиксацию цикла до полного HP, редактирование интервала, смерть и остановку.
Собственный 32-битный тестовый процесс проверяет Unicode-команду, десять
вызовов подряд и применение при HP 79%, 91% с остановкой на 100%.
Этот этап не изменяет игрового персонажа.
