# Автоматическое обнаружение подключений

Программа ищет установленные TCP-соединения процессов `l2.exe`,
`AsteriosGame.exe` и имени, указанного в профиле. Совпадение имени с профилем
расшифровки больше не является условием обнаружения. Адрес сервера и порт
берутся из сокета процесса. Единственное соединение принимается на любом
порту; известные игровые порты используются только для выбора среди
нескольких соединений одного клиента. При неоднозначности программа
сообщает об этом, а для нескольких клиентов можно выбрать PID в панели.

Автоматический выбор интерфейса учитывает локальный адрес соединения,
включая адаптеры виртуальных машин и VPN. Соединение с loopback или с тем же
локальным адресом направляется на Npcap Loopback. Ручной выбор интерфейса
сохраняет приоритет. Изменение соединения завершает текущую сессию;
обнаружение нового соединения выполняется автоматически.

Числовой PID больше не восстанавливается из предыдущего запуска: после
перезапуска клиента он меняется. По умолчанию включён автоматический выбор;
ручной выбор PID в текущем окне и явный аргумент `--pid` остаются доступны.

Совместимость расшифровки определяется отдельно по сборке `Engine.dll`.
Для проверенного профиля Asterios сохраняются прежняя расшифровка и действия.
Для другой сборки показываются подключение, PID, адрес сервера, число кадров
и захваченные TCP payload с точными исходными байтами. Статус явно сообщает,
что профиля расшифровки пока нет. Эти строки имеют opcode `TCP` и слой
`tcp-payload`; они не считаются игровыми пакетами, не обновляют инвентарь,
скиллы, HP или справочник наблюдений и не отправляются через очередь.
Сегменты TCP могут содержать часть игрового пакета или несколько пакетов.

Для полноценной работы с неизвестной сборкой клиента нужны соответствующие
ключи/алгоритм, схема протокола и обработчики действий. Универсальное
обнаружение соединения само по себе не подтверждает их совместимость.

Проверено на запущенном `MyTestServer/system/l2.exe` с соединением на порт
7777: автоматическое обнаружение и реальный захват данных без ошибок.
Впоследствии для этой сборки также подключена проверенная расшифровка:
[описание и результаты](classic-client-decryption.md).
Игра не перезапускалась, игровые действия не выполнялись. Результат:
live-source.json (`reports/universal-connection/live-source.json`).
Готовый EXE также обнаружил этот клиент автоматически и захватил реальные
данные без ошибок: live-exe.json (`reports/universal-connection/live-exe.json`).
Пройдены 153 автоматических теста и 177 проверок интерфейса готового EXE.
Автоматические проверки дополнительно охватывают произвольный порт,
несколько клиентов, неоднозначные соединения, выбор адаптера и loopback,
точное сохранение данных и отказ от трактовки TCP как игрового запроса.
