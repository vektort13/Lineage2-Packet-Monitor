# Единая программа для разных источников пакетов

Обновлён `dist-update-itemlist/L2PacketMonitor.exe`. Девятая вкладка
«Источники» объединяет автоматический выбор, захват сети, захват открытых
пакетов внутри проверенного клиента и приём от серверного модуля.
Все прежние восемь вкладок сохранены.

## Поток данных

`Auto → проверенный native adapter → общий декодер → модели/таблицы/очередь`.
Если адаптер открытого захвата не подключён или не запустился, Auto использует
проверенный сетевой профиль; для неизвестной сборки остаётся TCP без выдуманных
полей. В явном режиме «Клиент» отсутствие адаптера показывается как причина
ожидания, без автоматической подмены источника.

Клиентский источник копирует C → S перед оригинальным encrypt и S → C после
оригинального decrypt. Изменяется только копия исходящего opcode. Штатная
функция вызывается ровно один раз с исходными аргументами. Захвату не нужны
сессионные ключи или сборка TCP. Для текущего 557c9f6d проверены отдельные
слоты callbacks и сигнатуры кода. Исходный сетевой декодер остаётся доступным.

Нативное кольцо ограничено 128 пакетами и поддерживает конкурентные направления
через CAS-резервирование. Первоначальный вариант терял единичный пакет при
одновременном C/S; этот вариант и отчёт сохранены отдельно. Исправленный
`tap_hook_v2.dll` выдержал 50 C + 50 S пакетов по 32768 байт без потерь.
Состояние потерь выводится отдельно. При потере модели отмечают разрыв,
а клиентский источник повторно запрашивает полные списки инвентаря и скиллов.
Остановка восстанавливает оригинальные callbacks; повторный старт того же
процесса проверен. DLL хранится в неизменяемом кэше по SHA-256 и закрепляется
до выхода клиента для безопасности уже выполняющихся вызовов.

Серверный источник принимает аутентифицированные полные открытые пакеты
от Java/Python SDK. Пакет SDK с текущей конфигурацией экспортируется из EXE;
его точки `capture` нужно подключить в исходниках конкретного сервера после
расшифровки/до шифрования. Чужие серверные исходники не изменялись.
Локальный HTTP-приёмник работает без установки служб. Для удалённого сервера
описан SSH-туннель в README SDK. Одновременно в модели входит один выбранный
сеанс: другой publisher отклоняется до остановки и нового запуска захвата.
Числа sequence обнаруживают повторы и пропуски, проверка всего batch предшествует
изменению моделей. Python/Java проверены на 20 максимальных пакетах каждый;
размер HTTP batch остаётся меньше 1 MiB. Этот источник не включает нативные
игровые действия без соответствующего клиентского контекста.

`packet_sources.py` объединяет декодеры `classic-h5`, `asterios-448` и `raw`.
Последний сохраняет открытые байты без назначения полей известного протокола.
Статусы сохраняют различие: `plaintext_verified` для клиентской копии,
`source_authenticated` для сообщения моста и отдельный
`cipher_end_state_verified` для проверенного сетевого расшифрования.

## Сохранение и перенос

Оба исходных профиля и четыре реализации алгоритмов сохранены. В таблице видны
отпечаток сборки, алгоритм, протокол и наличие адаптера клиента. ZIP импорт/экспорт
содержит данные профилей, без сессионного состояния и исполняемых плагинов.
Импорт не повышает candidate до verified и не перезаписывает встроенные профили.
В EXE дополнительные профили хранятся в `%LOCALAPPDATA%/L2PacketMonitor/profiles/installed`,
поэтому переживают обновление/распаковку one-file EXE. Новая неизвестная защита
требует проверенного адаптера; наличие алгоритма в списке не доказывает поддержку
всех клиентов с похожим названием.

## Подтверждения

- 364 автоматических теста: `python -m unittest discover` с `src` в PYTHONPATH.
- 209 проверок интерфейса, двух языков и тем; в готовом EXE также выполнен
  реальный native mock обоих мостов и проверено наличие SDK.
- Клиентский native tap (`reports/new-client-decryption/client-plaintext-tap-live.json`):
  обе стороны и повторное подключение к реальному процессу.
- Общие исходники (`reports/unified-sources/live-source.json`): Auto/client,
  очередь 6/6, обновление скиллов, network/client переключение; 74 скилла,
  24 позиции инвентаря, без потерь и ошибок после исправления кольца.
- Готовый EXE (`reports/unified-sources/live-exe.json`): клиентский захват,
  очередь 6/6, экспорт обоих профилей и Java/Python SDK, приём сохранённых
  plaintext fixtures через упакованный серверный источник и возврат в Auto.
  Проверка моста является локальной проверкой потока данных, а не изменением
  живого удалённого сервера.

Подробности: [интерфейс](universal-sources-ui.md),
