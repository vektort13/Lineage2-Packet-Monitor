# Обучение скиллов из программы

Причина ошибки «Дождитесь синхронизации захвата» была в общей проверке
`actions_supported`: для новой сборки она запрещала и обучение, хотя захват
уже работал. Введена отдельная возможность `skill_actions_supported`.
Интерфейс и исполнитель используют её согласованно; неподключённый обработчик,
ожидание захвата и потеря соединения теперь имеют разные состояния.

Обычный RequestAcquireSkill 0x7C с ID 4683, уровнем 1, типом 0 действительно
ушёл через оригинальный обработчик и был расшифрован в захвате. Сервер прислал
SystemMessage 3028 и не добавил скилл в свежий SkillList:
live-source.json (`reports/new-client-decryption/skill-actions/live-source.json`).
Текст 3028 проверен в локальном SystemMsg-e.dat; он перечисляет ограничения
функции улучшения скиллов, но не устанавливает, какое именно условие сработало:
system-message-3028.json (`reports/new-client-decryption/skill-actions/system-message-3028.json`).

Затем записано успешное ручное обучение пользователя через серверное меню.
Фактический путь этой платформы — RequestBypassToServer 0x23, UTF-16LE
команда `_bbslearnSkills;learn;...`, а не обычный RequestAcquireSkill.
В записи подтверждены 19 изменений относительно предыдущих полных списков,
в том числе последовательные уровни скиллов 251 и 249:
packets.json (`reports/new-client-decryption/skill-actions/manual-learning/packets.json`).

Для окна обучения подключён тот же путь. Программа открывает меню и использует
его поиск; поиск сервера принимает названия, поэтому название берётся по ID
из локального каталога. Параметры класса, страницы и команды обучения берутся
из предложенного сервером HTML. Поддерживаются оба наблюдавшихся вида:
`_bbslearnSkills;learn;...` и `_bbslearnSkills_learnFromSearch_...`.
Их точные строки сохраняются; ID или уровень в готовой команде не подменяются.
Если сервер не предлагает нужную пару ID/уровень, программа сообщает об этом.

ShowBoard разбирается как восемь строк навигации и страница 101/102/103.
Фрагменты HTML склеиваются, включая команду, разрезанную между пакетами.
Поиск ожидает завершённый цикл страниц, чтобы предложение из страницы 102
не было пропущено после получения 101. Кэш предложений ограничен и очищается
при смене сессии или разрыве захвата. Для сервера без этого меню остаётся
обычный запрос обучения через проверенный обработчик данной сборки.

Команды вызывает существующий мост в оконном потоке клиента. Перед вызовом
проверяются Engine.dll, исходный код обработчика, профиль шифра и соединение.
Остальные игровые действия не включаются общей сменой флага. Успех обучения
требует захваченной исходящей команды и нового серверного списка с фактическим
уровнем; следующие уровни отправляются последовательно после подтверждения.

Оригинальный форматтер сохранён и проверяется отдельно в Unicorn:
formatter-check.json (`reports/new-client-decryption/skill-actions/formatter-check.json`).
Проверка подменяет только явно описанный bounded memcpy; она не выдаётся
за исполнение полной сетевой цепочки. Живой обмен проверяется отдельно.

При проверке EXE также исправляется [привязка TCP к состоянию клиента](classic-tcp-anchors.md):
одних конечных ключей и timestamp было недостаточно при задержке обработки.

Проверка исходников в текущем соединении:
live-menu-source.json (`reports/new-client-decryption/skill-actions/live-menu-source.json`).
Программа самостоятельно открыла меню, нашла Wind Walk по имени, выбрала
предложение для ID 1204 уровня 1 и получила подтверждение в SkillList:
уровень изменился с 0 на 1, задача завершилась `completed`.

оффлайн-вызова, включая реальные BBS-команды. Проверка интерфейса исходников
также прошла, включая отдельный флаг доступности обучения.
