# Очередь C → S для клиента 557c9f6d

Серый запуск очереди при работающей расшифровке вызывал общий флаг
`actions_supported=False`. Поддержка списков и обучения уже была подключена
к другому обработчику этой сборки; очередь продолжала проверять старый флаг.

Для очереди добавлена отдельная возможность `packet_requests` в проверенном
профиле Engine.dll. `NativeSender` выбирает профиль по реестру и не включает
через него остальные игровые автоматизации. Другие сборки сохраняют прежний
обработчик. Неизвестная сборка не получает чужой обработчик отправки.

Полные расшифрованные клиентские пакеты проходят проверку u16-длины,
направления, границ основного и расширенного opcode. Тело передаётся без
семантической подмены запроса в оригинальный c/cb-отправитель 0x203d9b50
в оконном потоке клиента. При каждом вызове проверяются процесс, соединение,
Engine.dll и код обработчика; шифрование и изменение native-состояния выполняет
клиент. Отдельное сопоставление обоих словарей opcode формирует TCP-привязку
для захвата, включая расширенный D0. Проверка словаря производится до вызова
клиента. Сессионные ключи не попадают в API, историю очереди или реестр.

В очередь на скриншоте пользователя были добавлены MagicSkillUse и
MoveToLocation направления S → C. По уточнению пользователя нужны действия
на сервере через C → S. Входящие ответы не преобразуются в вымышленные запросы.
Они остаются доступными как копии, но целиком блокируют отправку очереди
с номером строки и видимой причиной. Та же причина доступна в tooltip кнопки
и GET /api/packet-queue. Кнопка «Выбрать пакеты C → S» открывает вкладку пакетов
с фильтром исходящих запросов.

Каждый отправленный пакет подтверждается новым клиентским пакетом с точными
байтами в захвате. Следующая отправка начинается после подтверждения предыдущей;
интервал 0 означает отсутствие дополнительной задержки, а не отказ от проверки.
Повторы, пауза, остановка, смена соединения и отсутствие подтверждения сохраняют
свои существующие правила.

Проверки исходников: 291 unit-тест и 188 проверок интерфейса. Добавлены случаи
отдельной возможности очереди, точных байтов без переинтерпретации, неизвестной
сборки, максимального тела 32766 байт, расширенной перестановки opcode,
отказа до вызова native-обработчика и отсутствия ключей в результате.

Живая проверка исходников (`reports/new-client-decryption/packet-queue/live-source.json`):
повторены ранее захваченные запросы инвентаря 14, скиллов 50 и открытия
меню 23. Два цикла без дополнительного интервала завершили шесть отправок.
Отдельно проверены пауза/продолжение, остановка при паузе и отказ всей очереди
при добавлении S → C. Все десять исходящих пакетов получили отдельные новые
номера в захвате, байты совпали, конечные состояния шифра проверены;
ошибок синхронизации нет. Живая проверка не утверждает, что сервер исполняет
любые произвольно изменённые поля: решение о действии остаётся у сервера.
