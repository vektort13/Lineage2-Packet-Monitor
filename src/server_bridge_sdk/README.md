# L2 plaintext bridge SDK

Этот пакет подключает **ваш сервер с доступным исходным кодом** к L2PacketMonitor.
Получатель и интерфейс находятся в одной программе. SDK — небольшой адаптер внутри
сервера; он не устанавливает службы и не меняет игровой протокол.

1. В программе выберите серверный источник и запустите захват. Экспортируйте SDK.
2. Распакуйте ZIP. `bridge.json` содержит локальный адрес и токен текущего запуска.
   После перезапуска получателя экспортируйте свежую конфигурацию. Не публикуйте токен.
3. В сервере создайте один sender и отдельное соединение SDK для каждого игрового
   соединения. Создавайте новый UUID при каждом входе/переподключении.
4. **C → S / `client`:** после расшифровки и сборки одного полного пакета, перед
   обработчиком запроса, скопируйте открытый пакет в `capture`.
5. **S → C / `server`:** после сериализации одного полного ответа, до шифрования,
   скопируйте открытый пакет в `capture`.
6. При остановке сервера вызовите `close()` sender. В программе выберите нужную
   сессию/перезапустите захват при смене персонажа согласно интерфейсу.

`capture` принимает **полный открытый пакет: u16 little-endian длина, opcode,
payload**. Длина включает два собственных байта. Если серверная библиотека снимает
этот заголовок раньше или добавляет позже, создайте копию с `(body.length + 2)` и
телом; игровой буфер не изменяйте. Не передавайте случайные TCP-фрагменты,
шифротекст или общий буфер из нескольких пакетов. Для входящих запросов с
перемешанными opcode точка интеграции должна быть после обратного преобразования
opcode, для исходящих — до преобразования. Выбор версии протокола должен
соответствовать фактическим полям; `raw` сохраняет байты без обещания разбора статов.

## Python 3

Скопируйте `bridge_sender.py` рядом с серверным кодом:

```python
from bridge_sender import BridgeSender

sender = BridgeSender.from_file("bridge.json")
connection = sender.begin_connection("classic-h5")  # на новом игровом соединении
connection.capture(full_decrypted_request, "client")
connection.capture(full_serialized_response, "server")
# server shutdown:
sender.close()
```

## Java 8+

Добавьте `L2PlaintextBridge.java` в исходники сервера (при необходимости добавьте
строку `package` под ваш проект). Внешние зависимости не нужны. Значения `endpoint`
и `token` возьмите из `bridge.json` через уже используемый сервером загрузчик JSON
или его конфигурацию:

```java
L2PlaintextBridge sender = new L2PlaintextBridge(endpoint, token, 1024);
L2PlaintextBridge.Connection connection = sender.beginConnection("classic-h5");
connection.capture(fullDecryptedRequest, "client");
connection.capture(fullSerializedResponse, "server");
// server shutdown:
sender.close();
```

Проверка компиляции: `javac -source 8 -target 8 L2PlaintextBridge.java`.
Названия классов/методов точек расшифровки зависят от платформы. SDK не подключает
неизвестные серверные сборки автоматически; вставки выше нужно сделать в их коде.

## Потери и порядок

Сетевой ввод-вывод выполняет фоновый поток с ограниченной очередью (1024 пакета
по умолчанию). Игровой поток копирует пакет и ставит его в очередь без ожидания
HTTP. Общий номер `sequence` монотонен для обоих направлений одного соединения.
При заполнении очереди номер всё равно увеличивается; следующий полученный пакет
явно отмечает пропуск. Неуспешные HTTP-посылки также видны в счётчиках sender;
повторы после неоднозначного таймаута не отправляются. После последнего потерянного
пакета пропуск на приёмнике станет виден только при следующем полученном пакете.
`close()` завершает фоновый sender и учитывает неотправленный остаток как потери.
На старте/при пропуске полные списки инвентаря и скиллов нужно получить штатным
серверным/клиентским действием; SDK не выдумывает отсутствующее состояние.

Адрес слушает только `127.0.0.1`. Если сервер на другой машине, используйте
локальный туннель до ПК с программой и соответствующий loopback endpoint на сервере.
HTTP-приёмник не открывается в LAN/интернет, SDK не перенаправляет POST на другие URL.
Это односторонний канал захвата: он **не исполняет** команды в сервере и не
отправляет игровые запросы. Для повторения C → S в очереди нужен отдельно
проверенный транспорт текущей клиентской сборки.
